**Comprehensive SDK reference for AI agents editing NitroStack code**

## Architecture Overview

NitroStack uses **decorator-based architecture** inspired by NestJS:

- **Declarative** - Use decorators instead of factory functions
- **Modular** - Organize code into feature modules
- **DI-First** - Dependency injection for testability
- **Type-Safe** - Zod schemas for runtime validation
- **Protocol-Native** - Built for MCP protocol, not HTTP

### Key Principles

1. Use decorators (`@Tool`, `@Controller`, `@Module`, `@Injectable`)
2. No manual registration (`server.tool()`, `server.resource()`)
3. Constructor injection for dependencies
4. Services contain business logic, tools/controllers are thin
5. ES modules with `.js` extensions in imports

## Application Bootstrap

### Root Module (`app.module.ts`)

```typescript
import { McpApp, Module, ConfigModule, JWTModule, BM25SearchTransform } from '@nitrostack/core';
import { ProductsModule } from './modules/products/products.module.js';
import { OrdersModule } from './modules/orders/orders.module.js';
import { DatabaseService } from './services/database.service.js';

@McpApp({
  module: AppModule,
  server: {
    name: 'my-ecommerce-server',
    version: '1.0.0',
    description: 'E-commerce MCP server'
  },
  transforms: [
    new BM25SearchTransform({
      defaultLimit: 5,
      alwaysVisible: ['auth_login', 'system_status']
    })
  ],
  spillover: {
    maxPayloadBytes: 10240,
    previewItems: 3
  },
  logging: {
    level: 'info'  // debug | info | warn | error
  }
})
@Module({
  imports: [
    ConfigModule.forRoot(),      // Environment variables
    JWTModule.forRoot(),         // JWT authentication
    ProductsModule,              // Feature modules
    OrdersModule
  ],
  providers: [DatabaseService],  // Global services
  controllers: []                // Global controllers
})
export class AppModule {}
```

### Entry Point (`index.ts`)

```typescript
import { McpApplicationFactory } from '@nitrostack/core';
import { AppModule } from './app.module.js';

// Bootstrap application
async function bootstrap() {
  const server = await McpApplicationFactory.create(AppModule);
  await server.start();
}

bootstrap().catch((error) => {
  console.error('❌ Failed to start server:', error);
  process.exit(1);
});
```

**That's it!** No manual server setup needed.

## Controllers & Namespacing

Controllers organize related tools, resources, and prompts under a shared namespace prefix. All tool and resource names defined inside a controller are prefixed automatically with `${prefix}_`.

### Controller Namespacing Example

```typescript
import { Controller, Tool, InitialTool, ExecutionContext } from '@nitrostack/core';
import { z } from 'zod';

@Controller('finance')
export class FinanceController {
  // Registered in MCP protocol as 'finance_get_ledger'
  @Tool({
    name: 'get_ledger',
    description: 'Fetch general ledger records',
    inputSchema: z.object({
      accountId: z.string().describe('Target account ID')
    }),
  })
  async getLedger(input: { accountId: string }, ctx: ExecutionContext) {
    return { accountId: input.accountId, balance: 1000 };
  }

  // Registered as 'finance_bootstrap_session' and executed automatically on startup
  @InitialTool({
    name: 'bootstrap_session',
    description: 'Initial finance workspace setup tool',
  })
  async bootstrap(input: any, ctx: ExecutionContext) {
    return { status: 'ready', initializedAt: new Date().toISOString() };
  }
}
```

### Registering Controllers in Modules

```typescript
import { Module } from '@nitrostack/core';
import { FinanceController } from './finance.controller.js';
import { FinanceService } from './finance.service.js';

@Module({
  name: 'finance',
  controllers: [FinanceController],
  providers: [FinanceService],
```

## Transforms Pipeline

Transforms optimize tool visibility, progressive discovery, and code execution at the MCP protocol level before tools reach the model.

### Progressive Discovery with BM25 (`BM25SearchTransform`)

Hides exhaustive tool definitions behind a single `search_tools` meta-tool, dynamically exposing relevant tools on demand while preserving critical bootstrap tools:

```typescript
import { BM25SearchTransform } from '@nitrostack/core';

@McpApp({
  module: AppModule,
  server: { name: 'enterprise-server', version: '1.0.0' },
  transforms: [
    new BM25SearchTransform({
      defaultLimit: 5,                                 // Max tools returned per search
      alwaysVisible: ['auth_login', 'system_status'],  // Tools never hidden
    }),
  ],
})
export class AppModule {}
```

- **Meta-Tool Injected**: `search_tools({ query: string, limit?: number })`
- **Token Reduction**: Decreases prompt context token usage by up to 98% in large toolsets.

### Sandboxed Code Mode (`CodeModeTransform`)

Executes batch data processing scripts securely within isolated QuickJS WebAssembly worker threads:

```typescript
import { CodeModeTransform } from '@nitrostack/core';

@McpApp({
  module: AppModule,
  server: { name: 'code-mode-server', version: '1.0.0' },
  transforms: [
    new CodeModeTransform({
      workerPoolSize: 4,                        // Concurrent WASM worker threads
      memoryLimitMb: 128,                       // RAM cap per VM instance
      timeoutMs: 15000,                         // Hard execution timeout
      alwaysVisible: ['data_aggregate_sum'],    // Regular tools kept visible
    }),
  ],
})
export class AppModule {}
```

- **Meta-Tools Injected**:
  - `search({ query: string, limit?: number })` - Discover available SDK API tools
  - `get_schema({ toolName: string })` - Inspect input/output schema for code generation
  - `execute({ code: string })` - Execute JavaScript code invoking Nitro tools in a sandbox

## Guards

Guards implement authentication/authorization.

### JWT Guard

```typescript
import { Guard, ExecutionContext, Injectable } from '@nitrostack/core';
import jwt from 'jsonwebtoken';

@Injectable()
export class JWTGuard implements Guard {
  async canActivate(context: ExecutionContext): Promise<boolean> {
    const authHeader = context.metadata?.authorization;
    
    if (!authHeader || !authHeader.startsWith('Bearer ')) {
      return false;
    }
    
    const token = authHeader.substring(7);
    
    try {
      const payload = jwt.verify(token, process.env.JWT_SECRET!);
      
      // Attach auth info to context
      context.auth = {
        subject: payload.sub,
        email: payload.email,
        ...payload
      };
      
      return true;
    } catch (error) {
      context.logger.warn('JWT verification failed', { error });
      return false;
    }
  }
}
```

### Admin Guard

```typescript
@Injectable()
export class AdminGuard implements Guard {
  async canActivate(context: ExecutionContext): Promise<boolean> {
    // Assumes JWTGuard ran first
    const user = context.auth;
    
    if (!user) {
      return false;
    }
    
    // Check if user is admin
    return user.role === 'admin';
  }
}

// Usage: Multiple guards (all must pass)
@Tool({ name: 'delete_user' })
@UseGuards(JWTGuard, AdminGuard)
async deleteUser(input: any, ctx: ExecutionContext) {
  // Only admins with valid JWT can call this
}
```

## Middleware

Middleware runs before/after tool execution.

### Logging Middleware

```typescript
import { Middleware, MiddlewareInterface, ExecutionContext } from '@nitrostack/core';

@Middleware()
export class LoggingMiddleware implements MiddlewareInterface {
  async use(context: ExecutionContext, next: () => Promise<any>): Promise<any> {
    const start = Date.now();
    
    context.logger.info('Tool starting', {
      tool: context.toolName,
      input: context.input
    });
    
    try {
      const result = await next();
      
      const duration = Date.now() - start;
      context.logger.info('Tool completed', {
        tool: context.toolName,
        duration: `${duration}ms`
      });
      
      return result;
    } catch (error) {
      const duration = Date.now() - start;
      context.logger.error('Tool failed', {
        tool: context.toolName,
        duration: `${duration}ms`,
        error
      });
      throw error;
    }
  }
}

// Usage
@Tool({ name: 'my_tool' })
@UseMiddleware(LoggingMiddleware)
async myTool(input: any, ctx: ExecutionContext) {}
```

### Auth Middleware

```typescript
@Middleware()
export class AuthMiddleware implements MiddlewareInterface {
  async use(context: ExecutionContext, next: () => Promise<any>) {
    if (!context.auth) {
      throw new Error('Unauthorized');
    }
    
    return next();
  }
}
```

## Interceptors & Data Spillover

Interceptors intercept and transform execution input or output streams.

### Transform Interceptor

```typescript
import { Interceptor, InterceptorInterface, ExecutionContext, UseInterceptors } from '@nitrostack/core';

@Interceptor()
export class TransformInterceptor implements InterceptorInterface {
  async intercept(context: ExecutionContext, next: () => Promise<any>): Promise<any> {
    const result = await next();
    
    // Wrap all responses in standard format
    return {
      success: true,
      data: result,
      timestamp: new Date().toISOString(),
      tool: context.toolName
    };
  }
}

// Usage
@Tool({ name: 'get_product' })
@UseInterceptors(TransformInterceptor)
async getProduct(input: any) {
  return { id: '1', name: 'Product' };
}
```

### Data Spillover Interceptor (`DataSpilloverInterceptor`)

Automatically intercepts large tool responses and diverts the full payload to a temporary file while returning a truncated preview to the LLM to avoid context window overflow:

```typescript
import { Tool, UseInterceptors, DataSpilloverInterceptor, ExecutionContext } from '@nitrostack/core';

@Tool({
  name: 'dump_records',
  description: 'Fetch high-volume financial transaction history',
})
@UseInterceptors(new DataSpilloverInterceptor({
  maxPayloadBytes: 10240, // 10KB threshold
  previewItems: 3         // Retain first 3 items in preview
}))
async dumpRecords(input: any, ctx: ExecutionContext) {
  return await this.service.fetchMassiveData();
}
```

**Spillover Response Structure:**
```json
{
  "_spillover": true,
  "file": "/tmp/spillover-a1b2c3d4.json",
  "totalItems": 1500,
  "byteSize": 412850,
  "preview": [{ "id": 1 }, { "id": 2 }, { "id": 3 }],
  "message": "Payload exceeded 10240 bytes. Full data persisted to disk."
}
```

## MCP Tasks

MCP Tasks allow for long-running, asynchronous operations with progress updates and cancellation.

### Enabling Tasks

Set `taskSupport` to `'optional'` or `'required'` (defaults to `'forbidden'`).

```typescript
@Tool({
  name: 'audit_data',
  description: 'Audits large datasets (asynchronous)',
  taskSupport: 'optional', // or 'required'
  inputSchema: z.object({ datasetId: z.string() })
})
async auditData(input: any, ctx: ExecutionContext) {
  // Use ctx.task helpers
  if (ctx.task) {
    ctx.task.updateProgress('Scanning headers...');
    ctx.task.throwIfCancelled();
  }
  return { results: [] };
}
```

### Task Helpers (`ExecutionContext.task`)

- `task.updateProgress(message: string)` - Sends a status update to the client.
- `task.requestInput(message: string)` - Transition task to `input_required` state.
- `task.throwIfCancelled()` - Throws `TaskCancelledError` if client requested cancellation.
- `task.isCancelled` - Boolean flag for cooperative cancellation checks.
- `task.taskId` - Unique ID for the current task.

## Multi Round-Trip Requests (MRTR)

SEP-2322 compliant interactive conversational workflows requiring client confirmation or step-by-step inputs before proceeding:

```typescript
import { Tool, ExecutionContext, inputRequired, acceptedContent } from '@nitrostack/core';
import { z } from 'zod';

@Tool({
  name: 'transfer_funds',
  description: 'Initiate bank transfer with interactive user confirmation',
  inputSchema: z.object({
    recipientId: z.string(),
    amount: z.number().positive(),
  }),
})
async transferFunds(input: { recipientId: string; amount: number }, ctx: ExecutionContext) {
  // Check if confirmation was provided in previous round-trip
  if (!acceptedContent(ctx.metadata?.inputResponses, 'confirm')) {
    return inputRequired({
      requests: [
        {
          id: 'confirm',
          message: `Confirm transfer of $${input.amount} to account ${input.recipientId}?`,
          schema: { type: 'boolean' },
        },
      ],
      requestState: {
        recipientId: input.recipientId,
        amount: input.amount,
        step: 'awaiting_confirmation',
      },
    });
  }

  // Confirmation received; proceed with transfer
  return {
    status: 'success',
    transactionId: 'tx_998877',
    transferred: input.amount,
  };
}
```

## Modern Protocol (MCP 2026-07-28 Dual-Spec)

NitroStack natively supports both modern MCP 2026-07-28 (Streamable HTTP on `/mcp`) and legacy SSE (`/sse`):

```typescript
import {
  MODERN_PROTOCOL_VERSION, // '2026-07-28'
  LEGACY_PROTOCOL_VERSION, // '2025-06-18'
  PROTOCOL_ENV_VAR,        // 'NITRO_MCP_PROTOCOL_VERSION'
  inputRequired,           // Multi Round-Trip Request helper
  acceptedContent,
  EXT_APP,                 // 'io.modelcontextprotocol/app'
  EXT_TASKS,               // 'io.modelcontextprotocol/tasks'
} from '@nitrostack/core';
```

- **Protocol Negotiation**: Default era is `auto` (routes modern clients to Streamable HTTP `/mcp` while transparently supporting legacy SSE `/sse`).
- **Multi Round-Trip Requests (MRTR)**: Return `inputRequired({ ... })` for interactive conversational tool steps.
- **Client ID Metadata Documents (CIMD)**: Modern replacement for OAuth dynamic client registration (RFC 7591) via `createClientIdMetadataDocument`.

```typescript
'use client';

import { useEffect, useState } from 'react';

export default function ProductCard() {
  const [data, setData] = useState<any>(null);

  useEffect(() => {
    // Listen for data from Studio/MCP
    const handleMessage = (event: MessageEvent) => {
      if (event.data.type === 'toolOutput') {
        setData(event.data.data);
      }
    };

    window.addEventListener('message', handleMessage);
    return () => window.removeEventListener('message', handleMessage);
  }, []);

  if (!data) {
    return <div>Loading...</div>;
  }

  return (
    <div style={{ padding: '20px', border: '1px solid #ddd' }}>
      <h2>{data.name}</h2>
      <p>Price: ${data.price}</p>
      <img src={data.image_url} alt={data.name} style={{ maxWidth: '200px' }} />
    </div>
  );
}
```

### Basic Health Check

```typescript
import { HealthCheck, Injectable } from '@nitrostack/core';

@Injectable()
export class SystemHealthCheck {
  @HealthCheck('system')
  async checkSystem() {
    const uptime = process.uptime();
    const memory = process.memoryUsage();
    
    return {
      status: uptime > 0 ? 'up' : 'down',
      message: 'System is operational',
      details: {
        uptime: `${Math.floor(uptime)}s`,
        memory: `${Math.round(memory.heapUsed / 1024 / 1024)}MB`
      }
    };
  }
}
```

```typescript
// Custom error class
export class NotFoundError extends Error {
  constructor(resource: string, id: string) {
    super(`${resource} with ID ${id} not found`);
    this.name = 'NotFoundError';
  }
}

@Tool({ name: 'get_product' })
async getProduct(input: any) {
```

### Event Emission

Do NOT use `ctx.emit()`. Use top-level `emitEvent()` from `@nitrostack/core`:

```typescript
import { emitEvent, ExecutionContext, Tool } from '@nitrostack/core';

@Tool({ name: 'create_order' })
async createOrder(input: any, ctx: ExecutionContext) {
  const order = await this.orderService.create(input);

  // Emit event asynchronously across listeners
  emitEvent('order.created', {
    orderId: order.id,
    userId: ctx.auth?.subject,
    timestamp: new Date().toISOString(),
  });

  return order;
}
```

## Common Patterns

### CRUD Operations

```typescript
export class ProductsTools {
  constructor(private productService: ProductService) {}
  
  // Create
  @Tool({
    name: 'create_product',
    inputSchema: z.object({
      name: z.string(),
      price: z.number(),
      category: z.string()
    })
  })
  @UseGuards(JWTGuard, AdminGuard)
  async create(input: any) {
    return await this.productService.create(input);
  }
  
  // Read
  @Tool({
    name: 'get_product',
    inputSchema: z.object({ product_id: z.string() })
  })
  @Cache({ ttl: 60 })
  async get(input: any) {
    return await this.productService.findById(input.product_id);
  }
  
  // Update
  @Tool({
    name: 'update_product',
    inputSchema: z.object({
      product_id: z.string(),
      name: z.string().optional(),
      price: z.number().optional()
    })
  })
  @UseGuards(JWTGuard, AdminGuard)
  async update(input: any) {
    return await this.productService.update(input.product_id, input);
  }
  
  // Delete
  @Tool({
    name: 'delete_product',
    inputSchema: z.object({ product_id: z.string() })
  })
  @UseGuards(JWTGuard, AdminGuard)
  async delete(input: any) {
    await this.productService.delete(input.product_id);
    return { success: true };
  }
}
```

### Pagination Pattern

```typescript
@Tool({
  name: 'list_products',
  inputSchema: z.object({
    page: z.number().default(1),
    limit: z.number().default(20).max(100),
    category: z.string().optional()
  })
})
async listProducts(input: any) {
  const offset = (input.page - 1) * input.limit;
  
  const products = await this.productService.list({
    limit: input.limit,
    offset,
    category: input.category
  });
  
  const total = await this.productService.count({ category: input.category });
  
  return {
    products,
    pagination: {
      page: input.page,
      limit: input.limit,
      total,
      pages: Math.ceil(total / input.limit)
    }
  };
}
```

## Key Rules for AI Agents

1. **Always use decorators** - Use `@Tool`, `@Controller`, `@Module`, `@Injectable` (no factory functions)
2. **Constructor injection** - Never use `new ClassName()` for services; use DI
3. **Services for logic** - Tools and controllers should remain thin wrappers
4. **Zod for schemas** - All tool inputs must have `inputSchema` defined
5. **Return JSON** - All tool outputs must be JSON-serializable
6. **ES modules** - Always use `.js` in imports, never `.ts`
7. **ExecutionContext** - Handler context parameter (provides `logger`, `auth`, `verifiedSubject`, `task`, `abortSignal`)
8. **Never use `ctx.emit()`** - Always import and call `emitEvent('event.name', payload)` from `@nitrostack/core`
9. **Spillover for large payloads** - Use `DataSpilloverInterceptor` when tool output may exceed LLM context bounds
10. **Progressive discovery** - Use `BM25SearchTransform` or `CodeModeTransform` for large tool surfaces

Every tool your server registers is normally sent to the client in `tools/list`, schema and all. With a few tools that's fine. With hundreds, the catalog alone can fill the model's context before the conversation starts. Transforms sit between your tools and the client and reshape that catalog: they can hide tools until they're needed, replace the catalog with a search tool, or let the model run several tools from one script.

## Why transforms

A large catalog costs tokens on every request and gives the model more tools to confuse with each other. Transforms send a small, stable catalog instead, and reveal the rest on demand.

## How a catalog request flows

Transforms run in the order you list them in `@McpApp`. A typical setup filters hidden tools first, then collapses what's left into a search tool.

<Flow steps={[
  { title: 'tools/list', sub: 'From the client', icon: 'Bot' },
  { title: 'Registered tools', sub: 'Everything your server declares' },
  { title: 'VisibilityTransform', sub: 'Drops hidden tools for this session' },
  { title: 'Search or Code Mode', sub: 'Collapses the catalog' },
  { title: 'What the client sees', sub: 'Meta-tools and alwaysVisible tools', icon: 'Eye' },
]} />

You add transforms in `@McpApp`:

```typescript
@McpApp({
  module: AppModule,
  server: { name: 'enterprise-service', version: '1.0.0' },
  transforms: [
    new VisibilityTransform(),
    new BM25SearchTransform({ defaultLimit: 5, alwaysVisible: ['auth_login'] }),
  ],
})
```

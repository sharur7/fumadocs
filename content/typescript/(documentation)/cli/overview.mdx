The NitroStack CLI creates, runs, builds, and packages NitroStack MCP servers. Every project starts from an official [template](/docs/templates), and the same CLI then takes it from your first edit to a deployable build. For every command and option in one place, see [CLI Commands](/docs/cli/cli-commands).

## One CLI per language

Each SDK has its own command line. TypeScript projects use `nitrostack-cli` from the `@nitrostack/cli` package, and Python projects use `nitrostack-py`, which is installed with the `nitrostack` package. The commands have the same names wherever they do the same job, so the code samples on these pages have a tab for each language.

```bash tab="TypeScript" tab-group="language"
nitrostack-cli --help
# or, without installing:
npx @nitrostack/cli --help
```

```bash tab="Python" tab-group="language"
nitrostack-py --help
# or, if the script isn't on your PATH:
python -m nitrostack.cli.main --help
```

A few commands exist in only one CLI. `build` and `cursor` are TypeScript only; a Python project has no compile step, and runs straight from its source. `validate`, which checks a project before you deploy it, and `register`, which adds the server to Claude Desktop, are Python only.

## The development loop

A typical project moves through the commands in this order:

1. Run `init` to create the project.
2. Run `dev` to start the server with hot reload, and connect [NitroStudio](/docs/studio/overview) to it.
3. Run `generate` to add modules, tools, and other components as the server grows.
4. Test your changes in Studio.
5. Package the project for production and run it.

```bash tab="TypeScript" tab-group="language"
npx @nitrostack/cli init my-server
cd my-server
npm run dev
nitrostack-cli generate module payments
npm run build
npm start
```

```bash tab="Python" tab-group="language"
nitrostack-py init my-server --template python-starter
cd my-server
nitrostack-py dev
nitrostack-py validate
nitrostack-py pack
nitrostack-py start
```

Stuck? See [Troubleshooting](/docs/troubleshooting).

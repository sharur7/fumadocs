This section documents the public API of both NitroStack SDKs: every decorator, the pipeline interfaces, the execution context, and [the CLI](/docs/cli/overview) commands. Each page shows TypeScript first, with the Python equivalent in a tab wherever one exists. Pick a language once and every tab on the site follows it.

## TypeScript and Python at a glance

Both SDKs share the same mental model (modules, controllers, providers, and a [request pipeline](/docs/getting-started/core-concepts/request-lifecycle)), but the APIs follow each language's conventions. Don't copy TypeScript examples into a Python project, or the other way around.

| | TypeScript | Python |
| :-- | :-- | :-- |
| Package | `@nitrostack/core` | `nitrostack` (`pip install nitrostack`) |
| CLI | `nitrostack-cli` (`@nitrostack/cli`) | `nitrostack-py` (also `python -m nitrostack.cli.main`) |
| Decorators | PascalCase: `@Tool`, `@Module`, `@Injectable` | snake_case: `@tool`, `@module`, `@injectable` |
| Input schemas | Zod (`z.object(...)`) | Pydantic v2 `BaseModel` as `input_schema` |
| Dependency injection | Constructor parameter types | `@injectable(deps=[ServiceA, ServiceB])` + constructor args |
| Pipeline | `@UseGuards` / `@UseMiddleware` / `@UseInterceptors` / `@UsePipes` / `@UseFilters` | `use_guards` / `use_middleware` / `use_interceptors` / `use_pipes` / `use_filters` |
| Widgets | Next.js app in `src/widgets` | Static HTML under `widgets/out/{route}.html` + `@widget` |
| Build step | `nitrostack-cli build` | None (`nitrostack-py` has no `build` command) |
